# MyBooks CRM — приложение продажника (Flutter)

Чаты как в WhatsApp (текст, голосовые, фото, файлы, ответы на сообщения) плюс то, ради чего оно сделано: быстрые ответы
(шаблоны CRM), счета на оплату из чата, сделки и задачи, уведомления. Приложение ходит в тот же сервер CRM, что и веб:
права, видимость «только свои», защита от чужих реквизитов в сообщениях — всё проверяет сервер.

Вкладки: **Чаты** · **Задачи** («Мой день»: просрочено, ждут ответа, пропущенные звонки, новые заявки, план месяца,
список задач с «позвонить» и «написать» в одно касание, «Все» и «Готово», колокольчик с лентой уведомлений) · **Сделки**
(новая сделка, принять или отклонить заявку, позвонить, задача) · **Клиенты** (поиск, карточка: контакты, покупки, книги,
заказы, сделки, задачи) · **Профиль** (смена, уведомления). Из чата диалог можно передать коллеге.

## Запуск

```bash
cd mobile
flutter pub get
# на сервер mybooks.kz:
flutter run
# на локальный сервер (симулятор видит localhost; токен для отладки — необязательно):
flutter run --dart-define=SERVER_URL=http://localhost:3000
```

На экране входа адрес сервера можно поменять («Адрес сервера»). Вход — e-mail и пароль сотрудника, при включённой 2FA —
код из приложения-аутентификатора. Клиентским аккаунтам вход закрыт.

Если `pod install` падает на «Unicode Normalization»: `export LANG=en_US.UTF-8 LC_ALL=en_US.UTF-8`.

## Как устроено

- API — `src/app/api/mobile/*` на сервере (токен сессии в `Authorization: Bearer`, те же сессии, что у веба). Действия
  (отправить, перенести сделку, выставить счёт) — те же server actions, что в CRM; ничего не дублируется.
- Живые обновления — SSE `/api/admin/live/stream`; список чатов и открытый диалог обновляются сразу.
- Голосовые: запись m4a → сервер перекодирует в Ogg Opus (формат голосовых WhatsApp) через ffmpeg; входящие Ogg Opus
  сервер отдаёт приложению в AAC, потому что iPhone Opus не играет (`/api/mobile/chats/messages/<id>/audio`).
- Дизайн — `lib/ui`: токены (`tokens.dart`), общие элементы (`kit.dart`), значки Lucide (как в веб-CRM).

## Уведомления

| Когда | Что приходит | Нужно |
| --- | --- | --- |
| Приложение открыто | плашка сверху со звуком и вибрацией | ничего |
| Свёрнуто или закрыто (iPhone) | системное push-уведомление, число на значке, по нажатию открывается диалог или сделка | ключ APNs на сервере (ниже) |

Что уведомляется (сервер, `notify()` → `pushTo()`): новое сообщение клиента в вашем чате (ничей — всем с правом чатов; пока
бот ведёт опрос — итог бота), вам передали чат или сделку, задача и напоминание о сроке, оплачен счёт, клиент оформил заказ,
@упоминание, норматив ответа вышел, системное (кассир Kaspi отключён). Тихие часы и «push о сообщениях» — личные настройки
в CRM. Одно уведомление на объект: новое о том же чате заменяет прежнее (APNs `apns-collapse-id`, на Android — тег).
Нажатие открывает диалог, сделку, клиента или заказ; обращения, финансы и настройки — CRM на сайте. Открыли чат (в приложении
или в CRM) — его уведомления снимаются в колокольчике, пропадают из шторки, число на значке iPhone обновляется тихим push.

### iPhone — APNs (без Firebase)

1. developer.apple.com → Certificates, Identifiers & Profiles → **Keys** → «+» → включить *Apple Push Notifications
   service (APNs)* → скачать файл `AuthKey_XXXXXXXXXX.p8` (скачивается один раз). Запишите **Key ID** и **Team ID**
   (команда приложения — `MN7BW2N3B7`).
2. Capability *Push Notifications* и *Background Modes → Remote notifications* уже прописаны в `Runner.entitlements` и
   `Info.plist`; идентификатор приложения — `kz.mybooks.mybooksSeller`.
3. На сервере (`ssh srv@185.102.75.191`, файл `~/mybook/.env`):

   ```
   APNS_KEY_ID=XXXXXXXXXX
   APNS_TEAM_ID=MN7BW2N3B7
   APNS_KEY_FILE=/home/srv/mybook/AuthKey_XXXXXXXXXX.p8   # или APNS_KEY_P8 — текст ключа (переводы строк как \n)
   APNS_TOPIC=kz.mybooks.mybooksSeller                    # по умолчанию он же
   ```

4. Перезапустить сайт (`pm2 restart mybook --update-env`). Телефон сам регистрирует токен при входе; сборки из Xcode шлют на
   sandbox APNs, TestFlight и App Store — на production (определяется сборкой, можно задать `--dart-define=APNS_ENV=…`).

### Android — Firebase Cloud Messaging (без пересборки)

В приложении нет `google-services.json`: данные проекта Firebase телефон получает с сервера (`GET /api/mobile/push`) и
поднимает Firebase сам (`android/.../Push.kt`), уведомления рисует `MessagingService` (сервер шлёт только data). Значит,
ключ можно добавить на сервер когда угодно — уже установленное приложение подхватит его при следующем открытии.

1. console.firebase.google.com → создать проект (например «MyBooks CRM») → «Добавить приложение» → Android, имя пакета
   **`kz.mybooks.mybooks_seller`** → скачать `google-services.json` (из него нужны `mobilesdk_app_id` и `current_key`).
2. Настройки проекта → **Сервисные аккаунты** → «Создать закрытый ключ» → скачается JSON сервисного аккаунта.
3. На сервере в `~/mybook/.env`:

   ```
   FCM_SERVICE_ACCOUNT_FILE=/home/srv/mybook/firebase-service-account.json   # или FCM_SERVICE_ACCOUNT='{…}' одной строкой
   FCM_ANDROID_APP_ID=1:1234567890:android:abcdef0123456789                  # mobilesdk_app_id из google-services.json
   FCM_API_KEY=AIza…                                                          # current_key из google-services.json
   ```

4. Перезапустить сайт. Проверка: открыть приложение на Android → в базе `crm_mobile_devices` появится строка `android`.

Без ключей всё остальное работает: пока приложение открыто — плашки сверху со звуком; напоминания по задачам приложение
ставит на телефон само (до 40 ближайших своих задач, на время «срок минус напоминание»), а когда сервер умеет слать push на
этот телефон, расписание на телефоне не используется — повторов нет. Проверка без сервера на симуляторе: `xcrun simctl push
booted kz.mybooks.mybooksSeller payload.json` (пример тела — `apnsBody` в `src/modules/workspace/infrastructure/apns.ts`).

## Паритет с веб-CRM (21.10.2026)

В приложении есть то же, что в чате CRM на сайте: выбор нескольких сообщений (долгое нажатие → «Выбрать», «Переслать»,
«Удалить» или меню чата), пересылка в до 10 диалогов, удаление пачкой, личное закрепление чатов (долгое нажатие по чату),
личные шаблоны ответов (Профиль → «Шаблоны ответов»: редактор с заготовками, подсветкой подстановок, форматированием и
предпросмотром WhatsApp), вызов шаблона по «/» в поле ввода, «Создать шаблон (/)» из сообщения (код и ИИ заменяют данные
клиента подстановками), тёмная тема (Профиль → «Внешний вид»: Авто / Светлая / Тёмная) и автоматический выход на смену
при открытии приложения в рабочее время. Сервер: `/api/mobile/templates*`, `/api/mobile/chats/{id}/pin|forward`,
`/api/mobile/chats/targets`. Версия 1.1.0+2.

Сборка APK: `flutter build apk --release` (подпись — `android/key.properties`), готовый файл кладём в `build/MyBooks-CRM.apk`.

## Раскладки по ролям (v1.2.0)

Набор вкладок зависит от прав роли (сервер отдаёт `layout` в `/api/mobile/me`, логика — `src/shared/domain/mobileLayout.ts`, в приложении — `lib/core/layouts.dart`): руководитель — «Обзор», чаты, сделки, заказы, «Ещё»; продажи — чаты, задачи, сделки, клиенты; производство — заказы и задачи; аналитика — «Обзор» и заказы; поддержка — переписка. Разделы, которых нет во вкладках, — в «Профиле» / «Ещё». Новые экраны: «Обзор» (`/api/mobile/overview`), «Заказы» и карточка заказа со сменой статуса (`/api/mobile/orders*`). Та же раскладка в установленной CRM (PWA) — `docs/features/pwa-mobile.md`.

## Версия 1.3.0 (24.11.2026): быстрые чаты, push на Android, паритет с CRM

**Скорость чатов.** Список чатов и каждый диалог лежат в кэше телефона (`lib/core/cache.dart`, своя папка у сотрудника,
стирается при выходе): вкладка и переписка открываются сразу, свежее приходит следом; непрочитанные диалоги кладутся в кэш
заранее. Живое обновление открытого диалога — только последние 40 сообщений (`GET /api/mobile/chats/<id>/messages`) с ETag
(без изменений — пустой 304), шапка, шаблоны и счета — не чаще раза в минуту; история догружается при прокрутке вверх
(`?before=`), переход к цитате догружает её. Список чатов — тоже с ETag, поиск — после паузы в наборе. Все запросы идут по
одному соединению (keep-alive, без TLS-рукопожатия на каждый). Колокольчик опрашивается по событию «уведомление», а не по
каждому сообщению; при возврате в приложение поток событий переподключается сразу.

**Чаты как в CRM.** Карточки каталога WhatsApp (товар, корзина клиента с «Показать состав», ссылка на каталог), «Товар» в
«Прикрепить» — выбор из каталога с поиском и фото (`/api/mobile/catalog`, `/api/mobile/chats/<id>/catalog`); правки и
удаления клиентом в WhatsApp («Клиент изменил», «Удалено клиентом», прежние версии — в меню сообщения); файл, истёкший у
WhatsApp; «Повторить отправку» сообщения, которое шлюз не принял (`…/messages/<mid>/resend`); ответ бота — голубым пузырём,
не ушедший — красным; «Обращение в поддержку» из меню чата — с перепиской.

**Деньги и сделки.** «Принять оплату» / «Возврат» в карточке сделки — с формой оплаты из CRM и чеком (тот же
`POST /api/admin/deals/<id>/payments`, повтор после сбоя — тот же платёж), выбор «по счёту или другая оплата»; у платежей —
как пришли деньги и форма оплаты; смена ответственного по сделке. В заказе «Оплачен» без записи платежа больше не
предлагается.

**Дизайн.** Палитра CRM (`html.crm`, DESIGN.md): тушь, холодные серые, винный акцент, свои сообщения — rose, светлая и
тёмная тема; аватары и плитки — тонами CRM вместо градиентов WhatsApp.

## Выпуск

- **Android** — `flutter build apk --release` (подпись `android/key.properties` + `android/app/upload-keystore.jks`, в git их
  нет — лежат в основной папке репозитория). Готовый APK загружается в CRM: «Сайт» → «Приложение для Android» (или
  `scripts/mobile/upload-apk.sh`); сотрудники скачивают его по `/api/admin/mobile-apk`.
- **iPhone** — архив `flutter build ipa` (или Xcode → Product → Archive) → App Store Connect / TestFlight. Нужны: вход
  владельца команды `MN7BW2N3B7` в Xcode (Settings → Accounts), сертификат Apple Distribution и запись приложения
  `kz.mybooks.mybooksSeller` в App Store Connect.

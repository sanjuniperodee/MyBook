# Режимы книги: «Автобиография» и «Вручную»

Решение владельца 17.10: к четырём книгам-подаркам (любимому, маме, папе, другу) добавляются два режима создания книги.

- **Автобиография** — книга о своей жизни. Вопросы рассказчику о его жизни, текст от первого лица. Пишет сам
  рассказчик или близкий с его слов (внук записывает историю дедушки). Получателя нет: «для детей и внуков» — это посвящение.
- **Вручную** — своя книга с нуля. Готовых вопросов нет: автор сам создаёт главы и разделы (заголовок в книге + текст),
  может оставить себе вопрос-подсказку, переименовать, переставить и удалить главы и разделы.

Обложка, страницы, фото, письма близких, макет, заказ и печать — как у остальных книг.

## 1. Модель

**1.1. Режим — это тема.** `books.theme` получает значения `autobiography` и `blank` (колонка текстовая, миграция не
нужна). `blank`, а не `manual`/`custom`: «manual» уже значит источник сделки и тег клиента в CRM, «custom» — свой вопрос.
Лёгкий модуль `src/lib/content/kinds.ts` (без банков вопросов — его импортируют клиентские компоненты):

```ts
export type BookKind = "gift" | "autobiography" | "blank";
export function bookKind(theme: string): BookKind;            // autobiography | blank | gift (всё остальное)
export type RecipientPolicy = "required" | "optional" | "none";
export function recipientPolicy(theme: string): RecipientPolicy; // gift — required, autobiography — none, blank — optional
export const hasQuestionBank = (theme: string) => bookKind(theme) !== "blank";
export const hasOutline = (theme: string) => bookKind(theme) === "blank"; // свои главы и разделы
```

**1.2. Темы.** `ThemeId` = love | mom | dad | friend | autobiography | blank. В `ThemeDef` — `kind` и `recipient`;
`recipientLabel`/`recipientPlaceholder` — необязательные (у автобиографии их нет). `getThemes(lang)` — все шесть
(мастер, CRM); `giftThemes(lang)` / темы с банком — для главной, /kniga, статей и теста «> 40 вопросов».
`BooksService.start` проверяет тему (`AuthoringError("unknownTheme")`), молчаливый откат на love остаётся только для
показа старых строк.

| | Автобиография | Вручную |
|---|---|---|
| Обложка / оформление по умолчанию | `leather` + `vintage` | `linen` + `classic` (пары проходят feedback.test) |
| Названия по умолчанию (ru) | «История моей жизни», «Моя жизнь», «Книга моей жизни», «Моим внукам» | «Моя книга», «Записки», «Истории», «Книга воспоминаний» |
| Поводы | birthday (юбилей), parents, newyear, other | все |
| Получатель | нет (поле скрыто везде; род получателя не используется) | необязателен («Для кого — необязательно»), без рода |

Списки названий ru и kk одной длины (смена языка сопоставляет по индексу).

**1.3. Банк автобиографии** — `src/lib/content/autobiography.ts` и `kk/autobiography.ts`, одинаковые ключи глав,
число вопросов, места эпиграфов и подсказок. Вопрос — к рассказчику на «вы» (его может задать и близкий), заголовок в
книге — от первого лица, род рассказчика — `{м|ж}` («Где я {родился|родилась}»). `[..|..]` запрещены (получателя нет).
Супруг — нейтрально («супруг или супруга», kk «жұбайыңыз»). Ключи глав (менять после запуска нельзя — на них держатся
смена языка и аналитика): `intro, roots, childhood, school, youth, work, love, children, home, times, trials, joys,
wisdom, letter`. Не меньше 60 вопросов. Подсказка первого вопроса объясняет запись со слов близкого: «пишите его
словами, от первого лица».

**1.4. Автобиография: кто записывает.** Автор книги (`authorName`, `authorGender`) — рассказчик: его имя на обложке и
титуле, по его роду склоняются вопросы. Новая колонка `books.recorded_by text not null default ''` — кто записал со
слов («внучка Аружан»); печатается на обороте титула: «Записано со слов автора — {recordedBy}» (kk: «Автордың айтуымен
жазып алған — {recordedBy}»). Мастер: «Чья это история?» — «Моя» / «Близкого человека — записываю с его слов»; во
втором случае поля «Имя рассказчика», «Рассказчик — мужчина/женщина», «Кто записывает (необязательно)». «Кому
посвящаете (необязательно)» заполняет посвящение (`dedication`), а не получателя.

**1.5. Главы ручного режима — таблица `book_chapters`:** `id uuid pk, book_id → books on delete cascade, key text
(uuid без «:», не `__letters`/`__gallery`), position int, title text not null default '', epigraph text not null
default '', created_at, updated_at`; `unique(book_id, key)`, `index(book_id, position)`. Только у книг `blank`: у
книг с банком названия глав по-прежнему из темы. Не jsonb в `books`: `BookRepository.save` пишет снимок книги целиком
и затёр бы параллельное переименование главы.

**1.6. Разделы** — строки `book_questions` с `question_key='custom'`, `chapter` = ключ главы, `title` — заголовок в
книге (может быть пустым → в печати разделитель), `prompt` — вопрос-подсказка для себя ('' если нет, не печатается),
`hint` null, `display_text` null. Инвариант: `position` у разделов книги — 0..N-1 подряд, по главам в их порядке.
Каждая операция заканчивается перенумерацией одним SQL (row_number по `book_chapters.position, book_questions.position,
created_at`); позиции глав — тоже 0..M-1.

**1.7. Новая книга `blank`** создаётся с первой главой (название из мастера, по умолчанию «Начало» / «Бастауы») и одним
пустым разделом — редактор открывается сразу на нём. Пустое состояние всё равно обязательно (после удалений).

**1.8. Текст пользователя не склоняется.** `applyGender` не применяется к строкам `question_key='custom'` (свои вопросы
в любых книгах и разделы `blank`) и к названиям глав из `book_chapters` — иначе «[Аня|Анна]» в тексте испортится.
Названия глав в печать — через `printableText`, пустое → «Без названия» (`book.untitledChapter`).

**1.9. Лимиты:** глав в книге ≤ 50; название главы ≤ 120 знаков; эпиграф ≤ 300; заголовок раздела ≤ 200;
подсказка ≤ 300; разделов — общий `MAX_QUESTIONS = 600`.

## 2. Операции ручного режима (только `blank`; в других темах — 409 `outlineNotAllowed`)

Сервис `BookOutlineService` (authoring), всё в `uow.run` с `loadBook(editable)` и `books.touch`:
`addChapter({title, afterKey?})` → глава + пустой раздел; `renameChapter(key, {title?, epigraph?})`;
`reorderChapters(keys[])` (полный порядок, тот же набор ключей); `deleteChapter(key)` — вместе с разделами (фото
отвязываются по FK и уходят в общую галерею — предупреждение в диалоге); `addSection({chapterKey, afterId?, title,
prompt})` (без afterId — в конец главы); `updateSection(id, {title?, prompt?})` — только custom;
`reorderSections([{id, chapter}])` (полный порядок, тот же набор id); удаление раздела — существующий DELETE.
Перед удалением и перестановкой клиент делает flush автосохранения.

Маршруты (через `api()`/`apiViewer()`, zod, как соседние): `POST /api/books/[id]/chapters`, `PATCH|DELETE
/api/books/[id]/chapters/[key]`, `PUT /api/books/[id]/chapters/order`, `POST /api/books/[id]/questions` принимает
`{chapterKey, afterId?, title, prompt}` для `blank` (старая форма `{afterId, prompt}` для своих вопросов остаётся),
`PATCH /api/books/[id]/questions/[qid]` — ещё `title`, `prompt` для custom, `PUT /api/books/[id]/questions/order`.

## 3. Где режим меняет поведение

**3.1. Прогресс — одна функция** в `kinds.ts`: `progressOf(kind, {answered, total, words})` →
`{ started, half, ready, textStepDone, short }`. Книги с банком — как сейчас по ответам (шаг «Текст» ≥ 10, почти готова
≥ 25, половина — answered·2 ≥ total). `blank` — по словам: шаг «Текст» и «не короткая» ≥ 1000, половина ≥ 1500, почти
готова ≥ 3000. Ей пользуются хаб, AgreementCard, readiness, воронка CRM (book_half/book_ready), автописьма
(nudge/almost), фильтр «почти готовы» в /admin/books и дашборд — пороги больше не расходятся (10/25/30).
`book_progressed` отправляется и когда у раздела меняется «корзина» слов (по 150), иначе у `blank` вехи не сдвинутся.

**3.2. Печать.** Названия и эпиграфы глав `blank` — из `book_chapters`, порядок глав — их позиции; пустые главы не
печатаются (редактор об этом говорит). Подписи по режиму в `BookContent` (PDF, HTML-полосы, 3D — одинаково): галерея
(автобиография — «Из семейного альбома», blank — «Фотографии»), строка «записано со слов» на обороте титула. Имена на
обложке — одна функция `coverNames(book)`: автобиография — только автор; остальные — как `coverNamesLine`. Название по
умолчанию у `blank` никогда не пустое. Примеры разворотов до первых ответов — свои у автобиографии и нейтральные у
`blank`. `LAYOUT_VERSION` + 1.

**3.3. Мастер** «Какую книгу пишете?»: четыре карточки подарков и отдельный ряд «Книга о себе» (автобиография) и
«Вручную — своя книга с чистого листа». Формы — §1.4 и: у `blank` автор, «Для кого — необязательно», название
(обязательно, с вариантами), «Как назовёте первую главу?», язык, повод.

**3.4. Редактор `blank`.** Заголовок раздела — крупное поле (h1), под ним свёрнутая «Подсказка для себя», текст;
оглавление: переименование главы в строке, выше/ниже, удаление с подтверждением, «+ Новая глава», «+ Раздел»,
перенос раздела выше/ниже и в другую главу; переход по id раздела (`?s=<id>`, `?q=N` — совместимость); пустые
состояния «Создайте первую главу» / «Добавьте первый раздел»; карточка прогресса «N разделов · ≈ X стр.»; телефон —
то же в Drawer, кнопки ≥ 40 px. Автобиография — обычный редактор с банком и «Свой вопрос», подсказки про запись со
слов близкого.

**3.5. Остальное по режиму:** хаб (главы `blank` из таблицы, «N разделов · X слов», CTA), список книг, настройки
(рассказчик и «кто записывает» у автобиографии; без рода получателя у обоих), обложка (поле получателя: скрыто /
«необязательно»; подпись автора «Имя рассказчика»), оборот (готовые фразы для обоих режимов), посвящение (подсказка
по режиму), письма близких (приглашение: автобиография — «соберите воспоминания о {author}», blank — «{author} пишет
книгу «{title}»»), поводы, readiness, CRM (тип книги, «→ получатель» только если есть, название сделки «Автобиография:
{author}» / «Своя книга «{title}»», `theme` в событии книги), автописьма (советы и пороги по режиму, ссылки без ?q
для пустой книги), корректор и помощник (вид книги в промпте и ключе кэша), отзывы (подписи тем), главная и /kniga
(блок новых режимов, посадочные ru/kk), события аналитики (`book_created` с видом книги).

## 4. Проверки

Банк автобиографии проходит content.test (паритет ru/kk, > 40 вопросов, нет `[..|..]`, `{..|..}` раскрываются); тема
`blank` исключена из проверок банка. Юнит: старт трёх видов книг (без получателя, первая глава у blank, recordedBy),
`unknownTheme`, операции оглавления с перенумерацией и проверкой набора, запрет в темах с банком, лимиты, progressOf,
сборка книги со своими главами и без склонения своего текста, coverNames. Интеграционные на PostgreSQL: перенумерация
после вставки/переноса/удаления, удаление главы с фото, порядок в PDF = порядок в редакторе. DOM: пустое состояние
редактора, оглавление с действиями, мастер трёх видов. Тесты словарей ru/kk и веса клиентского бандла (kinds.ts —
без банков).

# Дубли сделок: как их не плодить

Один клиент — одна карточка. Заявка из чата или звонка заводится «пустой» (без заказа, денег, тарифа и суммы). Когда менеджер
вносит договорённость (предоплата, тариф, цена), эта заявка не должна жить рядом со сделкой договорённости.

| Где | Что делается |
|---|---|
| Клиенты → «Новый клиент» со сделкой и предоплатой; «сделки по договорённости» существующему клиенту | После создания первой сделки «пустые» заявки клиента и его номера вливаются в неё (`DealsService.absorbRequests` — то же слияние, что кнопка «Объединить»: переписка, звонки, задачи, лента, деньги переходят). В заметке с условиями — номера влитых. |
| Клиенты → «Новый клиент» без сделки | Открытые заявки этого номера без клиента привязываются к аккаунту вместе с перепиской (`linkRequests`). |
| Сделки → «Новая» с суммой или тарифом | То же, что при создании клиента: пустые заявки клиента вливаются. |
| «Создать сделку» из чата; счёт из чата в диалоге без сделки | Берётся уже открытая сделка клиента/номера, новая заводится только если её нет. |
| Сайт: регистрация, книга, заказ (`SiteFunnelService.advance`) | Открытую сделку ищут и по номеру клиента (заявка могла прийти раньше аккаунта) и привязывают к нему. Книга начата/на половине/готова, когда заказ уже выигран (в окне «crm.mergeClosedDays»), — новой сделки нет, поля книги ложатся в выигранную. |

Не вливаются: сделки с заказом, деньгами, чеками, тарифом или суммой — это отдельные покупки (клиент заказал вторую книгу).

Разовая чистка накопившихся дублей: `npm run dedupe:deals` (пробный проход) и `npm run dedupe:deals -- --apply`. Привязывает
заявку к аккаунту только если у номера ровно один аккаунт. Тесты: `tests/sales.test.ts`, `tests/clients-onboarding.test.ts`.

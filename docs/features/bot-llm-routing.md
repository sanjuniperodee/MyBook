# Маршрутизация модели AI-продажника: Claude Haiku / Sonnet / Opus

Бот-продажник (`AiSeller`, `src/modules/messaging/application/botSeller.ts`) отвечает клиентам на **Claude** — это
единственная основная модель. Уровень Claude выбирается под каждое сообщение клиента; другие провайдеры (DeepSeek,
ChatGPT, OpenRouter, Groq, свой сервер) — только **запасные**: на них бот переключается, если Claude недоступен или его
ключ не задан.

| Уровень | Модель по умолчанию | Когда |
| --- | --- | --- |
| Haiku | `claude-haiku-5-5` | основной поток: приветствие, FAQ, сбор имени и контактов, квалификация, уточнение потребностей, обычное продолжение |
| Sonnet | `claude-sonnet-5-5` | возражение по цене или условиям, торг, подбор и сравнение вариантов, несколько связанных условий, повтор нерешённого вопроса, неуверенный ответ Haiku |
| Opus | `claude-opus-5-5` | редкие исключения: противоречивые условия, много взаимосвязанных ограничений, вопрос не решён и после Sonnet, Sonnet не прошёл проверку в сложном ходе |

Ориентир распределения — Haiku 90 %, Sonnet 9 %, Opus 1 %. Это не квота: слабую модель ради процентов бот не выбирает.

## Путь сообщения

1. Входящее сообщение → `MessagingService.ingest` → `QualifierBot` (таймер паузы) → `AiSeller.turn`.
2. `AiSeller.consult` собирает контекст: системную инструкцию (стабильная часть кэшируется у Anthropic на час), последние
   60 сообщений переписки, заметку о клиенте, известные поля сделки, оплату, вердикт кода по сроку, выбранные куски базы
   знаний, уроки, состояние беседы. Контекст один и тот же на любом уровне — при смене модели ничего не теряется.
3. **Выбор уровня** — `chooseSellerTier` (`src/modules/messaging/domain/botRoute.ts`): правила по тексту клиента (русский
   и казахский), состоянию беседы и вердикту по сроку. Отдельного запроса к модели ради маршрута нет.
4. **Запрос** — `sellerModel` (`src/modules/assistant/application/SellerModel.ts`): Claude нужного уровня → при
   временном сбое (429, 529, 5xx, сеть) одна повторная попытка после паузы (`retry-after`, не дольше 3 с) → отказ Haiku
   (у Haiku 5.5 нет серверного резерва) поднимает запрос на Sonnet → запасные провайдеры по порядку. У Sonnet и Opus
   отказ по соображениям безопасности сервер Anthropic сам повторяет на резервной модели (`fallbacks: "default"`). Всё —
   в пределах полутора таймаутов запроса (45 с).
5. **Проверка результата** кодом (`resolveSellerTurn`, `checkSellerReply`): схема JSON, суммы только из тарифов и фактов,
   ссылки только на сайт, номера, право на счёт, потолок беседы. Отсутствие ошибки API не считается доказательством
   правильности.
6. **Эскалация** внутри хода (не больше `maxExtra` повышений уровня):
   - ответ не по схеме или сбой модели → повтор на уровень выше;
   - ответ не прошёл проверку кода → переписывает уровень выше;
   - модель «не уверена» (`handoff = unsure`) → тот же ход на уровне выше, прежде чем звать менеджера;
   - Haiku → Sonnet всегда; Sonnet → Opus — только для сложных ходов (тяжёлый признак или сложность у порога Opus) и не
     из-за сбоя API; выше Opus — некуда.
   - переписка не влезла в окно модели → та же модель с последними 20 сообщениями.
7. **Действия в CRM** (поля сделки, счёт, подборка, напоминание) выполняет код в `AiSeller.apply` — один раз, по итоговому
   решению хода. Повторы и эскалации до этого места ничего не отправляют и не записывают; запись состояния — по версии
   (compare-and-set), счёт — с ключом идемпотентности `bot:<беседа>:<версия>`.
8. Все маршруты не ответили → прежний безопасный путь: повтор хода через минуту, на второй сбой — «передала менеджеру» и
   задача менеджеру.

Модель не вызывает инструменты сама: она возвращает структурированное решение (JSON-схема `sellerSchema`), а цены,
наличие, скидки, статус оплаты и факт выставления счёта берутся только из backend (CRM, «Цены и тарифы», оплаты). Поэтому
при смене модели нет истории tool calls, которую надо переносить: каждый запрос получает полный контекст хода.

## Признаки сложности

Очки (`chooseSellerTier`): возражение по цене +2, «подумаю / позже» +1, повторное возражение +1, торг или скидка +2,
сравнение вариантов +2, несколько условий сразу (дата, город, формат, оплата, количество, язык, срочность) +1…+3,
противоречие +3 (за каждое, до двух: «дешевле, но премиум»; печатную к дате, к которой её не успеть; «но при этом» при
нескольких условиях), нерешённый вопрос (клиент повторяет вопрос или пишет «вы не ответили») +2, три и больше вопросов
+1, срок впритык +1, счёт и оплата на кону +1, сбои в этой беседе +1, переговоры продолжаются на старшем уровне +1.

Sonnet — от `sonnetAt` (2) очков. Opus — от `opusAt` (6) очков **и** хотя бы один тяжёлый признак (противоречие, четыре
и больше условий, нерешённый вопрос после Sonnet). Длинное или недовольное сообщение без этих признаков остаётся на
Haiku. Напоминание молчащему клиенту и оценка «ждёт ли клиент ответа» — всегда уровень по умолчанию. Ночной разбор
бесед (`BotCoach`) — Sonnet.

## Настройки

«Интеграции» → **AI** → «Маршрутизация модели продажника» (или переменные окружения — они важнее админки):

| Настройка | Переменная | По умолчанию | Что |
| --- | --- | --- | --- |
| `seller.route` | `AI_SELLER_ROUTING` | `on` | `on` — уровни по сложности; `shadow` — отвечает уровень по умолчанию, выбор только в следе и статистике; `off` — как раньше |
| `seller.route.haiku` / `.sonnet` / `.opus` | `AI_MODEL_HAIKU` / `AI_MODEL_SONNET` / `AI_MODEL_OPUS` | `claude-haiku-5-5` / `claude-sonnet-5-5` / `claude-opus-5-5` | модели уровней |
| `seller.route.default` | `AI_ROUTE_DEFAULT_TIER` | `haiku` | уровень по умолчанию (нижняя граница) |
| `seller.route.sonnetEnabled` / `.opusEnabled` | `AI_ROUTE_SONNET_ENABLED` / `AI_ROUTE_OPUS_ENABLED` | `on` | выключить Sonnet или Opus ради экономии токенов: ход идёт на ближайший включённый уровень ниже, эскалация выключенный уровень пропускает (без Sonnet Haiku поднимается сразу на Opus — только там, где Opus уместен) |
| `seller.route.sonnetAt` / `.opusAt` | `AI_ROUTE_SONNET_AT` / `AI_ROUTE_OPUS_AT` | `2` / `6` | пороги очков |
| `seller.route.maxExtra` | `AI_ROUTE_MAX_EXTRA` | `2` | повышений уровня за одно сообщение клиента (0–4) |
| `seller.route.budget` | `AI_ROUTE_BUDGET_USD` | `0.5` | потолок расходов на беседу, $ (`0` — без потолка): защита от клиента, который пишет «сложно» ради Opus |
| `seller.route.dailyBudget` | `AI_ROUTE_DAILY_BUDGET_USD` | — | потолок расходов в сутки (по поясу магазина), $ |
| `seller.route.prices` | `AI_ROUTE_PRICES` | цены Anthropic | прайс, $ за 1M токенов: `{"модель": {"input", "output", "cacheRead", "cacheWrite"}}` |
| `seller.fallbacks` | `AI_SELLER_FALLBACKS` | прежний провайдер продажника | запасные провайдеры по порядку: `deepseek,openai` |

Ключ Claude — тот же, что у AI-помощника (`ai.apiKey` / `ANTHROPIC_API_KEY`, адрес — `ai.baseUrl`). На потолке расходов
бот отвечает только на Haiku, без эскалаций (клиент без ответа не остаётся).

Запасные провайдеры: пусто — тот, что был выбран для продажника раньше («Прежняя модель продажника» или провайдер
AI-помощника), если это не Claude, с прежней моделью (`seller.model`). Данные клиентов уходят только туда, куда уходили и
раньше; новых провайдеров бот сам не добавляет.

### Включить

Достаточно ключа Claude в «Интеграциях» → AI: маршрутизация включена по умолчанию (`seller.route = on`). Прежний провайдер
продажника (например, DeepSeek) остаётся запасным. Для осторожного запуска — сначала `shadow`: отвечает модель по
умолчанию, а в «Почему так?» и статистике бота видно, какой уровень выбрал бы маршрут.

### Выключить и вернуться к прежнему поведению

`seller.route = off` (форма или `AI_SELLER_ROUTING=off`): бот работает на одной модели из блока «Прежняя модель
продажника» (`seller.provider` / `seller.model`), без уровней, эскалаций и запасных — как до маршрутизации.

## Метрики и расходы

- **След хода** («Почему так?» у ответа бота, `crm_bot_events.kind = turn`, `meta.route`): выбранный уровень и коды
  признаков, эскалации с причиной, каждый запрос — зачем (ответ, повтор, пересчёт срока, переписать, уровнем выше, короче
  переписка), провайдер и модель, токены (вход без кэша, чтение и запись кэша, выход), стоимость по прайсу, задержка,
  запасной ли провайдер, неудачные попытки и вид сбоя. Текстов клиента и ответа, номеров и ключей там нет.
- **Лог сервера**: строка `[bot] llm call` на каждый запрос с теми же полями (id беседы, без текстов).
- **Статистика бота** (Бот → Статистика, 30 дней, `llmStats` в `persistence.ts`): доля ответов Haiku / Sonnet / Opus /
  запасной, что выбирал маршрут, эскалации, расходы и стоимость 1 000 ходов, токены с кэшем, сбои, повторы и ответы
  запасных.
- Расход беседы копится в состоянии (`ai.llmCostUsd`) — для потолка на беседу; суточный — суммой по журналу.

Прайс — одно место: `DEFAULT_PRICES` в `src/modules/assistant/domain/routing.ts` (Anthropic API, октябрь 2026: Haiku 5.5 —
$0.10 / $0.50, Sonnet 5.5 — $2 / $10, Opus 5.5 — $4 / $20 за 1M токенов; чтение кэша — 0.01 / 0.20 / 0.20; запись в кэш
на час — 2× входа) и перекрывающая его настройка `seller.route.prices`. Модели без цены (запасные провайдеры) считаются в
токенах, а стоимость — «нет в прайсе», а не ноль.

## Ограничения

- Цена Haiku 5.5 в прайсе — для запросов до 100K токенов (у продажника запрос в разы меньше); дороже тариф выше 100K
  не учитывается.
- Стоимость неудачного запроса (таймаут, отказ) считается нулевой: точное списание провайдера неизвестно.
- Подсказка менеджеру («Подсказать ответ» в чате) идёт тем же маршрутом, но в след и метрики не пишется и в потолок
  беседы не считается.
- AI-помощник менеджера, AI-корректор и распознавание голосовых и фото по-прежнему на своих провайдерах из «Интеграций».
- Признаки сложности — правила по словам; пороги стоит подстроить по статистике первых недель (режим `shadow`).

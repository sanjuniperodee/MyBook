# Чистка репозитория бэкенда, 27.11.2026 — опись (этап 1)

Просьба владельца: убрать из `mybook-backend` всё, что принадлежит вебу (`mybook-web`) и мобильному (`mybook-mobile`),
и разложить по местам. Этот файл — опись без изменений кода: что лежит, кто этим пользуется, есть ли копия в другом репо
и что с этим делать. Этапы 2 (сборка без `next build`) и 3 (перенос и удаление) — по этой описи.

## Как считалось

- **Кто импортирует** — esbuild с `metafile` от реальных входов (как собирает `scripts/node-bundle.mjs`, пакеты внешние):
  - бэкенд (рантайм): `apps/backend/src/main.ts` (backend.mjs), `apps/backend/src/worker.ts` (backend-worker.mjs),
    `src/worker/main.ts` (worker.mjs), `src/modules/production/infrastructure/pdf/worker.ts` (pdf-worker.mjs);
  - тесты: все `tests/**/*.test.ts(x)` (кроме `tests/visual`), `tests/backend`, `apps/backend/test` — по каждому файлу отдельно;
  - скрипты: все `scripts/**/*.{ts,tsx,mjs}`;
  - веб: все исходники `mybook-web/src` с его tsconfig (`@/*` → `src`, затем `shared/src`) — что веб берёт из пакета shared.
  Импорты только типов esbuild выбрасывает, поэтому файлы из одних типов (`ports.ts`, `repositories.ts`, `types.ts`)
  в счёт «никто не импортирует» не идут — они нужны.
- **Копия в вебе** — по каждому отслеживаемому файлу: тот же путь в `mybook-web` и тот же хэш; другой путь с тем же
  содержимым; «отличается» — и тогда есть ли версия бэкенда в истории `mybook-web` (значит веб впереди, копия бэкенда
  устарела) или такой версии в вебе никогда не было (уникальные правки бэкенда).

Главные выводы:

1. **Рантайм бэкенда не использует ни одного файла** из `src/app`, `src/components`, `src/hooks`, `src/web`,
   `src/proxy.ts`, `src/instrumentation*.ts` и `public/`. PDF (pdf-worker) — тоже: его вёрстка целиком в
   `src/modules/production/infrastructure/pdf` + `src/lib/book`. `src/components/interior/pdf-tree.ts` — это вёрстка
   **превью** (браузер), PDF она не нужна; нужна только тестам паритета превью↔PDF.
2. **Копия сайта в бэкенде устарела, веб — впереди.** Из 1 006 файлов веба в бэкенде (`src/app` 610, `src/components`
   282, `src/hooks` 3, `src/web` 17, `public` 17, корневые 3): одинаковых 646, тех же по содержимому под другим путём 111
   (веб переложил страницы в `(site)` / `(cabinet)`), отличающихся 143 — из них 136 в истории веба уже были (веб ушёл
   дальше), 7 «уникальных» разобраны ниже — переносить нечего; 36 файлов в вебе нет — веб их удалил или переписал
   (`photos-data.ts`, `inbox-items.ts`, `src/web/book-hub.ts`, старые `(app)/…/page.tsx`).
3. **Копия сайта держит две вещи бэкенда**: (а) сборку — `npm run build` начинается с `next build`, бандлы ложатся в
   `.next/standalone`; (б) состав пакета `mybook-shared` — `scripts/packages/build-shared.mjs` и
   `tests/web-boundary.test.ts` обходят импорты **от копии** `src/app`/`src/components`/`src/web`/`src/hooks` бэкенда.
   Поэтому сессии до сих пор правят копию «для пакета веба» (c4b4979e). После чистки входами обхода должен стать сам
   `mybook-web` (см. этап 3).
4. **65 тестов бэкенда тестируют интерфейс сайта** (импортируют `src/app`/`src/components`/`src/web`), а у веба тестов
   нет (`vitest.config.mts` есть, тестовых файлов ноль).
5. **130 файлов `src/server` мертвы**: `src/server/site-handlers/**` (127), `src/server/{invite,shelf,site-chrome}.ts` —
   их импортировала только копия `src/app/api/**`; маршруты давно переписаны на Nest (`@SiteRoute` в `apps/backend`).
   Ещё 28 файлов `src/server` нужны только тестам (старые обработчики маршрутов, `mobile-api.ts`, `v1-proxy.ts`).

## План этапов 2 и 3 (кратко)

**Этап 2 (ворктри `claude/cleanup-backend`):** бандлы — esbuild напрямую в свою папку сборки (например `build/`), без
`.next/standalone`: `backend.mjs`, `backend-worker.mjs`, `pdf-worker.mjs`, `worker.mjs` (ещё нужен: откат воркера
`MYBOOK_WORKER_RUNTIME=legacy`). Внешние пакеты (`pg`, `sharp`, `@react-pdf/*`…) копирует `traceExternals` в
`<сборка>/node_modules`. `pack-release.sh` — из новой папки + `assets`, `drizzle`; без `.next/static` и `public`.
`deploy.sh`/`rollback.sh`/`ecosystem.config.cjs` — релиз без `server.js` (сайт на сервере уже выключен флагом;
запасной путь «сайт на сервере» уходит вместе с копией сайта — это и есть просьба владельца). `smoke-bundles.mjs` — по
новой папке. CI: `npm run build` без `next build`, без ключа серверных действий Next. Сравнить размер релиза и память.

**Этап 3 (после «nest-apps-api» и «nabludaemost» или без пересечений):**
1. `build-shared.mjs` и `web-boundary.test.ts`: входы обхода — из `mybook-web` (путь к checkout веба в CI —

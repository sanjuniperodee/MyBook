## Цель 1 — веб без прямого доступа к БД (A5 до конца)

1. Переводи раздел за разделом. Порядок: кабинет и полка → книга и редактор (главы, ответы, фото, письма, обложка) →
   заказ и оплата → публичные страницы (главная, темы, отзывы, сертификаты, оферта) → CRM `/admin/*` (самое большое,
   последним).
2. Каждый раздел: маршруты и модели в `packages/contracts` → обработчики в `apps/api` (вызывают те же функции модулей)
   → страница берёт данные через `v1-web-client` → включи сверку `PARITY_MODE=shadow` на проде и проверь в логах, что
   расхождений нет → включи раздел во `WEB_USE_API_V1` (в `.env` прода, список через запятую) → убери строки из
   allowlist. Allowlist только уменьшается, тест-храповик не ослабляй.
3. Server actions (формы) тоже переводи: действие вызывает API v1, а не модуль. Загрузку файлов (фото, аудио, видео) делай
   через API с потоковой передачей. Буферизовать большие файлы в памяти Next нельзя.
4. Что остаётся только на сервере: вёрстка PDF (`pdf-worker`), ffmpeg, шлюзы WhatsApp, Kaspi, планировщик, вебхуки.
   Веб получает от них только результат через API.
5. В конце веб не импортирует ни `@/server/db`, ни модули с БД. Это проверяет тест архитектуры: allowlist пуст или
   содержит только явно описанные исключения с причиной.
6. Выкатывай по разделу, проверяй прод и пиши строку в `docs/microservices/PROGRESS.md`. UI не меняй.

## Цель 2 — пробная выкатка на Vercel для замера (только когда цель 1 готова хотя бы для кабинета и публичных страниц)

1. **Домен mybooks.kz не переключать.** Выкатывай на адрес Vercel (`*.vercel.app`). На Vercel только Next. Переменные:
   `API_INTERNAL_URL=https://mybooks.kz/api/v1` или отдельный поддомен API. Секретов БД на Vercel быть не должно.
2. Сессия: cookie `mb_session` должна работать на домене фронта. Продумай, как API принимает её с Vercel: тот же
   родительский домен через поддомен или Bearer. CORS открывай только для своего домена.
3. **Замер из Казахстана обязателен** (в Cloudflare 24.11 обожглись: Варшава дала +0,5 с). Сравни TTFB и полную
   загрузку главной, кабинета, книги и оформления заказа: Vercel против текущего сервера. Мерь из KZ (сервер
   185.102.75.191 или любая KZ-точка), минимум по 20 замеров. Выбери регион функций Vercel, ближайший к Алматы, и запиши,
   какой выбран.
4. Итог — таблица в `docs/microservices/vercel-trial.md`: цифры, регион, что работает и что нет. Рекомендация простая:
   переносить, только если не медленнее. Переключение домена — **только с «да» владельца**.

# domain

Книга хранится в одной строке `books` (src/shared/infrastructure/db/schema/authoring.ts:22-67). Поля: theme (text NOT NULL, без enum и CHECK, в комментарии перечислено love|mom|dad|friend), status, title, subtitle, authorName/authorGender, recipientName (NOT NULL DEFAULT ''), recipientGender (NOT NULL DEFAULT 'm'), hideRecipientOnCover, обложка, оборот, кадры фото, dedication, interior, format, photoPlacement, showToc, inviteToken, language, occasion и occasionDate. В миграциях (drizzle/0000_init.sql:20) тема тоже обычный text, так что новые id тем добавляются без миграции. Отдельной сущности «глава» нет. Глава — это текстовый ключ `book_questions.chapter` (:79), а её название в БД не хранится. Его вычисляют при каждом рендере из банка темы по ключу: chapterTitle()/bookTexts(); для незнакомого ключа берётся «Разное». Поэтому пустых глав, переименования и порядка глав отдельно от вопросов сейчас нет. Порядок задаёт только `book_questions.position`: и вопросов, и глав (глава встаёт по первому своему вопросу). Редактор и хаб группируют главы по подряд идущим вопросам, а сборка PDF — по ключу. При создании книги Book.start копирует вопросы банка (ключ `theme.chapter.N`) в book_questions. Свой вопрос — строка с questionKey='custom', prompt=title=текст пользователя. Он вставляется только ПОСЛЕ существующего вопроса и в ту же главу (insertAfter), удалить можно только свои вопросы. Существующие вопросы не правятся: менять можно лишь answer, displayText (переписанный заголовок вопроса) и hideHeading. При смене языка replaceTemplates по ключам переписывает prompt/title/hint стандартных вопросов. Ответы, свои вопросы и displayText остаются как были. Названия глав переводятся сами, потому что берутся из темы на языке книги. Название книги меняется, только если оно совпадало с предложенным вариантом. Главная скрытая ловушка: getTheme() для незнакомого id тихо возвращает тему love (themes.ts:113), то есть книга с новой темой получит любовные вопросы, названия и главы. Сценарий (а) «без получателя» хранилище уже допускает: recipientName может быть пустым, PATCH пустую строку пропускает, coverNamesLine пустое имя обрабатывает. Мешают только мастер (zod min(1) и HTML required) и подписи/переключатели рода получателя. Для (б) нужны новая таблица глав, новые методы домена, репозитория и API, а также правки в редакторе: при 0 вопросов он падает, questions[-1].id. Хаб, список книг, readiness и воронка CRM на 0 вопросов не падают (деление защищено), но их проценты и пороги («10 ответов», «25/30 ответов») для режима «вручную» теряют смысл.

## risks
- getTheme() (src/lib/content/themes.ts:113) для неизвестного id тихо возвращает love. Если добавить 'autobiography'/'manual' только в БД или action, но не в base, книга получит любовные вопросы, названия «Наша история» и любовные главы. А Book.start запишет theme='love', потому что theme.id приходит из каталога (Book.ts:111). BooksService.start тему не валидирует (services.ts:26-28).
- Редактор падает при 0 вопросов: QuestionsEditor.tsx:63 даёт index=-1, а строка 80 обращается к q.id у undefined. То же происходит при удалении последнего раздела. В ручном режиме это первый экран.
- Названия глав в БД не хранятся: они вычисляются по ключу из темы, для чужого ключа — «Разное» (themes.ts:105-106,132-134; layout.ts:172). Без новой таблицы все главы ручной книги будут называться «Разное», а пустые главы существовать не могут.
- Порядок глав определяется position вопросов. Хаб (page.tsx:58-68) и редактор (editor-model.ts:95-103) группируют подряд идущие вопросы, а PDF (layout.ts:155-158) — по ключу. Если перенести раздел в другую главу без пересчёта position, глава разорвётся: в редакторе две группы и неверный posInChapter (QuestionsEditor.tsx:176-178), в хабе дубликат React-ключа, в книге одна глава.
- deleteCustom (persistence.ts:95-102) не перенумеровывает position, а письма-напоминания используют position как индекс ?q= (notifications/templates.ts:17,105). Уже сейчас после удаления своих вопросов ссылка может вести не туда. В ручном режиме с частыми удалениями и перестановками это станет заметно.
- DrizzleBookRepository.save (persistence.ts:37-42) перезаписывает весь снимок книги. Если хранить названия и порядок глав в jsonb на books, автосохранение обложки или настроек (updateSettings) затрёт параллельное переименование главы. Нужна отдельная таблица.
- applyGender применяется к тексту пользователя: title = prompt своего вопроса (editor-data.ts:28-30, layout.ts:81). Заголовки и подсказки ручного режима с конструкциями вида {а|б} или [а|б] будут искажены.
- Если titleSuggestions пуст, defaultTitle = undefined (book-content.ts:18, layout.ts:213): книга без названия упадёт или напечатается без титула. Для manual нужен хотя бы один вариант названия или fallback из словаря.
- Пустой заголовок раздела ('' в title при displayText=null) даёт heading='' вместо null (layout.ts:161): возможен пустой блок заголовка в вёрстке и оценке объёма.
- Метрики «ответов» не подходят ручному режиму: хаб «Отвечено на X% вопросов» (page.tsx:54,137), шаг «Текст» при ≥10 ответах (page.tsx:74), readiness «коротко» при <10 (readiness.ts:28), CRM book_half/book_ready (sales services.ts:350-357, порог 25), фильтр «почти готова» ≥30 (reporting Books.ts:17).
- Тест tests/content.test.ts:30-35 требует больше 40 вопросов в КАЖДОЙ теме, а :36-48 — полного паритета ru/kk. Тема manual с пустым банком его уронит, автобиографию нужно сразу писать на двух языках с одинаковыми ключами.
- Лендинг (src/app/page.tsx:250-262) и /kniga выводят все getThemes: появятся карточки с «0 вопросов» и сломается сетка на 4 колонки. В отзывах вместо подписи будет сырой id темы (admin/reviews/page.tsx:121), если не добавить review.showcase.theme.
- Для пустого получателя хранилище готово, но мастер блокирует создание: zod min(1) в actions.ts:23 и HTML required в NewBookWizard.tsx:125. Переключатель «Книга для» в мастере и настройках будет менять бессмысленный recipientGender (по умолчанию 'm').
- Смена языка для автобиографии работает только при одинаковых ключах `autobiography.<chapter>.<n>` в ru и kk. Переписанные заголовки (displayText), свои вопросы и названия глав пользователя не переводятся — это ожидаемо, но пользователь может удивиться.

## open
- Как представить режим: новыми значениями theme ('autobiography', 'manual') без миграции books (рекомендация) или отдельной колонкой mode? От этого зависят фильтр CRM по теме, отзывы и поводы.
- Нужно ли поле «кто записывает» для автобиографии (например recorded_by: «записала внучка Аружан» на обороте титула)? Если запись идёт со слов родственника, authorName/authorGender — это рассказчик (печатается как автор, по нему род в вопросах). Верно ли это допущение?
- Разрешать ли создание, переименование, перестановку и удаление глав, а также удаление стандартных вопросов в книгах с темой (включая автобиографию) или только в ручном режиме?
- Создавать ли в ручной книге сразу одну пустую главу «Глава 1», чтобы редактор не начинался с пустого экрана?
- Что делать с фото, вставленными в раздел, при удалении раздела или главы: удалять или переносить в общий пул (сейчас FK ON DELETE SET NULL)?
- Какие пороги готовности и прогресса для ручного режима — по словам, по страницам или по числу заполненных разделов? Это влияет на хаб, readiness, CRM-воронку и фильтр «почти готова».
- В ручном режиме «вопрос-подсказка» — это отдельное поле (prompt/hint), не печатается в книге, а печатаются заголовок (title/displayText) и текст (answer)? Можно ли оставлять заголовок раздела пустым (hideHeading)?
- Показывать ли «Автобиографию» и «Книгу с нуля» на лендинге и в /kniga рядом с четырьмя темами, и с каким текстом вместо «N вопросов»?

# 10. План: меньше ресурсов и быстрее обработка — Go там, где это окупается (2026-11-24)

> Поручение владельца 24.11: «спланируй переход на микросервисы и бэкенд на Rust или Go — максимально снизить
> потребление и ускорить обработку, сохранив весь функционал»; решения — за Claude. Решение — [ADR 0011](adr/0011-go-services-strangler.md).
> Продолжает [ADR 0009](adr/0009-modular-monolith-with-workers.md) (монолит + процессы), не отменяет его.

## 1. Замеры 24.11 (ночь, прод `185.102.75.191`, 4 ядра / 15 ГБ)

| Процесс | Память (RSS) | CPU |
|---|---:|---:|
| `mybook` (Next: страницы, API, server actions) | 529 МБ | 2,5 % |
| `mybook-worker` (планировщик, outbox, бот, правила, IMAP, ffmpeg-очередь) | 184 МБ | 0,2 % |
| `mybook-gowa` (WhatsApp, **уже Go**) | 60 МБ | 0,2 % |
| **MyBooks всего** | **~0,8 ГБ** | |
| Сервер: занято / доступно | 3,4 / 11,6 ГБ | load 0,2 |

- Вёрстка PDF, заказ 106 (52 полосы): печатные файлы (блок + обложка) — **3,2 с**, PDF для чтения — **1,8 с**,
  пик памяти временного процесса — **0,75 ГБ**, CPU 143 %.
- Страницы и API (perf.md, 05.11): сервер тратит 10–65 мс (p95), публичные — ~12 мс в среднем.
- База — 104 МБ, файлы — 1,1 ГБ (основное — S3).
- Код: ~217 тыс. строк TS, 156 `route.ts`, 45 файлов server actions, 17 модулей.

## 2. Что даст переписывание всего бэкенда (честная оценка)

| | Весь бэкенд → Go (Next только SSR/BFF) |
|---|---|
| Экономия памяти | Next SSR остаётся (~350–450 МБ: React-страницы рендерятся только в Node). Уходит доменный код и пул БД из Node (~100–150 МБ), worker 184 → ~30 МБ. **Итого ~0,8 → ~0,5 ГБ** |
| Скорость для клиента | Почти ноль: сейчас 10–65 мс сервера; добавится сетевой хоп BFF → API (+1–3 мс на запрос, ×N запросов на страницу) |
| Цена | 156 роутов + 45 файлов server actions + домены (деньги, Kaspi, бот, правила, вёрстка) — месяцы; дублирование DTO/правил на двух языках; риск потерять функционал |
| PDF | `@react-pdf/renderer` живёт только в JS; перенос вёрстки на Go/Rust ломает «книга везде одинаково» (превью в браузере и PDF считаются одним кодом) |

Вывод: **полное переписывание не окупается** — экономия ~0,3 ГБ при свободных 11,6 ГБ и без выигрыша в скорости.
Окупаются точечные участки, где Node делает «трубу» (байты, очереди, вебхуки) и контракт стабилен.

## 3. Rust или Go

- **Go** — для сервисов-«труб»: HTTP, стриминг файлов, очереди, вебхуки, планировщик. Тот же язык, что у GOWA
  (опыт патчей, сборка уже есть), быстрая компиляция, простой код для агентов, бинарник 10–30 МБ RSS.
- **Rust** — только для узкого CPU-ядра, если замер его найдёт (сейчас CPU-узких мест нет: картинки — libvips/C,
  видео — ffmpeg, PDF — 3 с на книгу). Не вводим без замера.

## 4. План по фазам (каждая — с гейтом «продолжать / остановиться»)

| Фаза | Что | Цель (метрика) | Гейт |
|---|---|---|---|
| **G1. Замеры** | Время и память вёрстки PDF, пересборок, отдачи файлов — в лог (`perf`), сводка `scripts/perf/*`; RSS процессов раз в 5 мин в таблицу/лог | Цифры по каждому тяжёлому участку | — |
| **G2. Быстрые победы без нового языка** | Node: `--max-old-space-size`/`--max-semi-space-size` по замеру, ленивые импорты тяжёлых модулей в `mybook` (pdf, sharp, ffmpeg, AI SDK) — чтобы web не держал то, что нужно worker'у; отдача файлов — без буферизации целиком в память (стримы, Range) | `mybook` 529 → ≤ 400 МБ; без регресса p95 | Если ≤ 400 МБ — G3 по желанию |
| **G3. Пилот на Go: `mybook-files`** | Отдача файлов и медиа: фото книг/превью, вложения CRM (`/api/admin/whatsapp/media`, `/api/admin/support/.../files`), видео по QR (`/v/<токен>`), с Range, кэш-заголовками, S3 PS Cloud и локальным хранилищем; проверка доступа — подписанным токеном, который выдаёт Next (HMAC `APP_SECRET`), без похода Go в права | Байты не идут через Node: RSS `mybook` под нагрузкой файлами не растёт; TTFB файла ≤ текущего; паритет байт-в-байт и заголовков | Паритет 100 % на выборке; иначе откат (nginx → Next) |
| **G4. Go-воркер очередей** | Только «труба»: забор `outbox_events`/задач из Postgres (`SKIP LOCKED`), доставка вебхуков/писем/WhatsApp-отправок через GOWA, ретраи. Доменные решения (правила, бот) остаются в TS-worker'е и кладут готовые задания в очередь | `mybook-worker` 184 → ≤ 120 МБ; задержка доставки не хуже | Если выигрыш < 50 МБ — не продолжать |
| **G5. Дальше — только по триггерам ADR 0009 §5** | Бэкенд-API на Go за BFF — если CI/команда/масштаб упрутся (3+ параллельных разработчика, 10× сообщений, отдельная машина) | — | — |

Сохранение функционала: каждый вынесенный маршрут — за флагом (nginx/`PARITY_MODE`), со сверкой ответов старого и
нового пути (`src/server/parity.ts`, golden DTO из волны 0), откат — переключением upstream без выкатки кода.

## 5. Инфраструктура

- Go-сервисы живут в репозитории: `services/<имя>/` (go.mod), сборка в CI (`go build`, `go test`, `go vet`),
  бинарник выкатывается тем же `deploy.sh` в релиз, запускается PM2 (как GOWA).
- nginx: маршруты файлов → `mybook-files` (нужен `sudo` на сервере — делает владелец по инструкции из `06-operations.md`,
  пока нет — Next проксирует на Go внутри: `rewrites` в `next.config.ts` на `127.0.0.1:<порт>`).
- Новых хранилищ (Redis, NATS, Kafka) не вводим: очередь — Postgres (ADR 0009 §1).

## 6. Что не делаем и почему

- Не переписываем вёрстку PDF и превью (паритет книги — один код).
- Не переносим авторизацию/права/деньги на Go (безопасность и деньги, выигрыша нет).
- Не делим базу и не вводим распределённые транзакции.

# Пробная выкатка фронта на Vercel (26.11.2026)

Цель 2 из `docs/handoff/antigravity-2026-11-26-web-api-vercel.md`. Домен mybooks.kz не трогали: проба — только на
https://mybooks-trial.vercel.app (проект `mybooks-trial`, команда bekkhans-projects, план **Hobby** — по условиям Vercel не
для коммерческого использования; для замера годится, для работы магазина — нужен Pro).

## Как выкачено

- На Vercel только Next (`vercel.json`: `next build`, без воркеров, PDF и mybook-api; `.vercelignore` — без тестов, мобильного
  приложения, документации). `output: "standalone"` только для нашего сервера.
- Переменные Vercel (секретов нет): `API_INTERNAL_URL=https://mybooks.kz`, `BACKEND_ORIGIN=https://mybooks.kz` (туда же
  `/api/v1/*` и `/files/*` из `next.config.ts`), `APP_URL=https://mybooks-trial.vercel.app`, `WEB_API_ONLY=1`,
  `STORE_TIME_ZONE=Asia/Almaty`, `MYBOOK_SKIP_TYPECHECK=1`. Нет `DATABASE_URL`, Kaspi, AI, S3, `APP_SECRET` — сборка без них
  проходит.
- Без `DATABASE_URL` `webApiOnly()` ведёт все разделы (кабинет, книга, заказы, публичные, CRM) только через API v1, без
  `WEB_USE_API_V1`: в логах Vercel после правок ни одного обращения к БД.
- Что пришлось поправить в коде (в master, на нашем сервере ничего не меняется):
  1. `src/instrumentation-node.ts` — на сайте без БД не запускать миграции, синхронизацию каталога и фон (иначе каждая
     страница падала на `ECONNREFUSED 127.0.0.1:5432`).
  2. `src/shared/domain/time.ts` — Vercel ставит `TZ=":UTC"` и не даёт его менять: пояс магазина берётся из
     `STORE_TIME_ZONE`, ведущее «:» отбрасывается (иначе CRM падала на `Invalid time zone`).
  3. `next.config.ts` — `BACKEND_ORIGIN` для переписывания `/api/v1/*` и `/files/*` (без него — 127.0.0.1, как было).

## Сессия

Cookie `mb_session` живёт на домене фронта (vercel.app): вход идёт server action → API v1, cookie ставит сам Next. Дальше Next
шлёт токен в API и как `Cookie: mb_session=…`, и как `Authorization: Bearer …` (`v1-web-client.ts`, `v1-proxy.ts`). Браузер
ходит только на свой домен, в API напрямую не ходит — CORS открывать не нужно. Проверено вживую: вход владельца на
mybooks-trial.vercel.app работает, кабинет и CRM (обзор, сделки, чаты, заказы, клиенты, задачи, доски, финансы, прибыль,
звонки, команда, настройки) открываются без ошибок.

## Что работает и что нет

- Работает: публичные страницы, вход, кабинет, CRM.
- Не готово к переносу:
  - IP клиента: nginx mybooks.kz перезаписывает `X-Real-IP` адресом Vercel. Лимиты по IP стали бы общими на всех,
    а правило сети CRM («вход только из офиса») — сломалось бы. Нужен заголовок с IP клиента, подписанный общим
    секретом Vercel ↔ API.
  - 12 мест считают дни по поясу процесса (`setHours(0…)`, `localDay`), а процесс на Vercel в UTC — перед переносом
    перевести на `storeTimeZone()`.
  - Hobby — не для коммерции.
  - Без прокси остались не-CRM маршруты `/api/v/[token]`, `/api/design-ai/packs`, `/api/media/oembed`, `/api/fonts`.

## Рекомендация

**Не переносить.** Vercel из Казахстана медленнее в 8–12 раз: TTFB 350–620 мс против 35–70 мс. Даже
пустой редирект на Vercel стоит ~360 мс — это сеть до ближайшей точки Vercel (Стокгольм), а не наш код. Каждая
страница ещё и ходит из функции обратно в API в Казахстане. Без точки Vercel в регионе или рядом выигрыша не будет.
Проект mybooks-trial можно удалить или оставить для следующего замера; домен не переключался.

# ADR 0011. Go для сервисов-«труб» по замерам; бэкенд целиком не переписываем

**Статус:** принято (владелец поручил решить, 2026-11-24) · **Дата:** 2026-11-24
**Дополняет:** [0009](0009-modular-monolith-with-workers.md) — снимает «Go — нет» для узких участков со стабильным
контрактом; остальное в 0009 в силе.

## Контекст

Владелец хочет снизить потребление ресурсов и ускорить обработку, сохранив функционал, и спрашивает про
микросервисы и бэкенд на Rust/Go. Замеры 24.11 — [10-go-plan-2026-11-24.md](../10-go-plan-2026-11-24.md) §1:
MyBooks занимает ~0,8 ГБ (web 529 МБ, worker 184 МБ, GOWA на Go 60 МБ), сервер отвечает за 10–65 мс, PDF на
52 полосы — 3,2 с. Полное переписывание дало бы ~0,3 ГБ экономии без выигрыша в скорости ценой месяцев работы
и риска для функционала; Next SSR остаётся на Node при любом варианте.

## Решение

1. **Язык новых сервисов — Go** (как GOWA). Rust — только для CPU-ядра, найденного замером.
2. **Выносим «трубы»**, а не домены: отдача файлов/медиа (G3), доставка очередей/вебхуков (G4). Доменная логика,
   деньги, авторизация, вёрстка книги остаются в TypeScript.
3. **Каждая фаза — с метрикой и гейтом** (план §4): нет выигрыша — не продолжаем; есть расхождение — откат.
4. **Без новых хранилищ и брокеров**: Postgres-очереди, S3, PM2, nginx.
5. Сначала быстрые победы без нового языка (G2).

## Последствия

- В репозитории появляется `services/` с Go-модулями; CI собирает и тестирует Go.
- Паритет ответов — обязательная часть каждого вынесенного маршрута (`src/server/parity.ts`, golden DTO).
- Целевое потребление MyBooks: ~0,8 → ~0,5 ГБ; пересмотр — по триггерам ADR 0009 §5.
